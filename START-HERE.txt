SETPOINT — how to pick up where you left off
=============================================

WHAT'S IN THIS FOLDER
  index.html   The entire app. One file. Open it in a browser to see it.
  CLAUDE.md    A project brief that Claude Code reads automatically every
               session, so you don't have to re-explain the project.
  START-HERE   This file.


STEP 1 — Open this folder in Claude Code
  Point Claude Code at THIS folder (the one containing index.html).


STEP 2 — Paste this as your first message
  ---------------------------------------------------------------
  Read CLAUDE.md. I want to deploy this to GitHub Pages and publish
  the Firestore security rules. Walk me through it step by step —
  I'm not experienced with the terminal or git.
  ---------------------------------------------------------------


FACTS CLAUDE CODE WON'T KNOW UNTIL YOU TELL IT
  - Firebase project ID: setpoint-f9948
  - Email/Password sign-in is already ENABLED in Firebase Auth.
  - Firestore database is already CREATED, in production mode.
  - The security rules have NOT been published yet. Until they are,
    sign-in will work but saving data will fail. This is the next step.


THE FIRESTORE RULES STILL TO PUBLISH
  In the Firebase console: Firestore Database -> Rules tab.
  Replace everything there with this, then click Publish:

    rules_version = '2';
    service cloud.firestore {
      match /databases/{database}/documents {
        match /users/{userId} {
          allow read, write: if request.auth != null
                             && request.auth.uid == userId;
        }
      }
    }

  This means: you can only read and write your own data, and only
  while signed in. Nobody else can reach it even if they find the URL.


TESTING IT LOCALLY
  Do NOT just double-click index.html. Firebase sign-in only accepts
  approved web addresses, and a local file isn't one of them —
  "localhost" is approved by default. So run a local server instead.
  Claude Code can do this for you; the command is:

    python3 -m http.server 8000

  Then visit  http://localhost:8000  in your browser.


WHY IT HAS TO BE HOSTED ONLINE FOR YOUR IPHONE
  iPhones can't run this kind of app from a file you AirDrop over —
  Safari blocks it. It needs a real https:// web address. That's what
  the GitHub Pages step is for. Once it's live, open the link in Safari
  on your phone and choose "Add to Home Screen" to get an app icon.
